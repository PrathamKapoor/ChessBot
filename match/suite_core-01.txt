# Phase 3C opening suite "core-01"
#
# Twelve starting positions, each a legal FEN reachable from the initial
# position, chosen to span game structures rather than to be famous test sets.
#
# WHY A FIXED SUITE
# Random openings make a small experiment impossible to repeat: two runs of the
# same A/B test would not face the same positions, and a difference in results
# could not be separated from the difference in openings. A fixed suite also means
# a per-opening breakdown is meaningful, because every position gets the same
# number of games.
#
# This is version "core-01" and it is not intended to be permanent. Later phases
# are expected to add suites rather than to edit this one, so that results
# recorded against core-01 stay comparable. The runner takes a suite path, so a
# later suite is a new file and not a code change.
#
# PROVENANCE
# Every position below is reached by playing the listed moves from the initial
# position. The move sequences are given so the FEN can be checked rather than
# trusted, and `tools/verify_openings.py` does exactly that. The FEN is the
# authoritative field; the moves exist to document how it was arrived at and are
# cross-checked against it.
#
# STRUCTURE COVERAGE
#   open       symmetric, undeveloped, lots of legal moves
#   closed     locked centre, minor pieces off
#   tactical   a concrete threat exists at the starting ply
#   queenless  no queens, evaluates pawn structure
#   opposite   the two sides castle on opposite wings
#   majority   a pawn majority, which the evaluator scores explicitly
#   endgame    a reduced-material position arising from a transition
#   asymmetric material advantage already established
#
# NOT included, deliberately: any position that is a known puzzle, and any
# position selected because a particular engine happens to like or dislike it.

#

# match/verify_openings.py's sibling generator, so the two cannot disagree.
